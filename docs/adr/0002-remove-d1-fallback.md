# ADR 0002: Web アナリティクスの D1 未設定フォールバックを削除

- ステータス: Accepted
- 日付: 2026-07-11
- 関連: ADR 0001

## コンテキスト

ADR 0001 では、D1 バインディング（`ANALYTICS_DB`）が無い環境でも計測を止めないよう、
`/api/hit` に Workers Logs への書き込みをフォールバックとして実装していた。

しかし D1 バインディングは `wrangler.toml` に `database_id` を含めて設定済みであり、
デプロイ先アカウントに D1 が存在しない状態は運用上想定しない。フォールバック経路は
実質的に使われないまま、`/api/hit` と `/admin/analytics` の双方に「D1 なし」を扱う
分岐・UI が残り、コードの複雑さと考慮漏れのリスクだけが増えていた。

## 決定

D1 バインディングが常に存在する前提に変更し、フォールバックを削除する。

- `src/pages/api/hit.ts` — `ANALYTICS_DB` が無い場合の `console.log` フォールバックを削除。常に D1 に `INSERT` する。
- `src/pages/admin/analytics.astro` — D1 未設定時のセットアップ手順表示を削除。`ANALYTICS_DASH_KEY` による認証チェックのみ残す。
- `wrangler.toml` の `[observability]` コメントから「D1 バインドが無い環境でのフォールバック保存先」という記述を削除。

別アカウントへデプロイする場合は、デプロイ前に D1 セットアップ（`wrangler d1 create` ＋
`schema.sql` 適用）を完了させることが前提になる。手順は README の「Web アナリティクス」節を参照。

## 影響

### 良い点

- `/api/hit`・`/admin/analytics` から「D1 なし」分岐が消え、コードが単純になる。
- 計測経路が D1 に一本化され、フォールバック経路の考慮漏れがなくなる。

### 割り切り・コスト

- D1 が未設定・障害中の環境では計測イベントが失われる（Workers Logs へのフォールバックはない）。
- 別アカウントへデプロイする際は、D1 セットアップを済ませてからデプロイする運用が必須になる。
